# SmartHR Reliability And Search Efficiency Review

Date: November 5, 2026 (Asia/Calcutta).
Application: https://effortsairecruiter.tech/.

## Changes

| Area | Implementation |
| --- | --- |
| Search parsing | `services/search_reuse.py` reuses extracted text only for identical original bytes, file path, bucket and user/workspace identity. Original bytes are still read, so replacements are not hidden by a path-only cache. Full text is preserved; empty, failed and oversized extraction is not retained. |
| AI token usage | The same service reuses only complete, high-confidence `llm_primary` keyword assessments for identical full CV text, ordered keywords, prompt, model/provider and user/workspace. Fallback/repaired/incomplete assessments are not cached. Concurrent identical work is coalesced. |
| Reuse limits | Process-local bounded LRU: 32 document entries with a five-minute reuse window, at most 256 KiB of UTF-8 text each; 64 keyword entries with a fifteen-minute window, at most 128 KiB of serialized result each. Expiration is checked on access. No new persistent CV copies or external cache service. |
| Duplicate submissions | `static/js/main.js:performRealSearch` shares an in-flight exact request only for the same user/workspace, full criteria, job title and candidate count. Results are copied for consumers; success/failure releases the guard. Different searches still run independently. This is not cross-device server-side idempotency. |
| UI | Search fields reserve space for upload/send controls on desktop and mobile; compact search-header spacing, visible keyboard focus, accessible sample-search activation, named upload control and reduced-motion support. Existing workflows and result views remain. |
| Dashboard | Local calendar dates avoid UTC day shifts. Upcoming-event content is escaped, stale responses ignored, and database/provider failures show a retryable unavailable state rather than a false empty schedule. Synchronous database work runs off the API event loop. |
| Outreach | Inputs and optional candidate-record ownership are validated before provider actions. Long meeting links fit the schema. Delivery success remains success if only audit logging fails; uncertain delivery/persistence is reported honestly without an automatic resend. |
| OAuth | Session-cookie compatibility, signed session-bound state, PKCE, encrypted tokens, credential refresh locking and safe missing-session recovery are retained. Administrator consent remains separate from recruiter account linking. |
| Source safety | Private runtime configuration is no longer tracked; `config.example.json` is the non-secret setup template. Local real configuration is preserved. CI rejects private config and scans the committed tree with redacted Gitleaks output. Legacy credential-shaped Kubernetes examples were cleared, not production configuration. |

Models, prompts, token ceilings, full-document analysis, exact-match filters and ranking rules were not weakened for these efficiency changes. Health checks remain provider-free by default.

## Remaining Acceptance Gates

- Fresh desktop/mobile screenshots could not be captured in this pass because browser control is disabled in Work settings. Automated DOM/responsive-navigation tests do not replace visual certification.
- Real email delivery, attachment-import acceptance and actual calendar/Teams event creation still need controlled end-to-end acceptance. No test emails, invitations or employment decisions were sent by this audit.
- 97 existing documents have no extracted text and no usable vector. Classify scanned, encrypted, legacy DOC or non-CV files before adding OCR/reindexing; do not manufacture matches to fill a requested count.
- No labeled CV/job-description precision/recall benchmark exists yet. Current evidence demonstrates preserved ranking, not a claimed accuracy improvement or universal exact-match guarantee.
- Cold-search latency still includes provider generation and strict-criteria candidate overfetch. Do not trim evidence, remove keyword analysis or change models without a representative quality benchmark. Production p50/p95 and paid-token savings depend on real reuse frequency and are not yet measured.
- Durable outreach idempotency/outbox reconciliation, off-site restore drills, sustained load/failover, physical mobile/Safari and full accessibility acceptance remain work items. The application is improved, not certified issue-free or ready for a million concurrent users.
