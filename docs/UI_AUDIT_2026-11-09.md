## Follow-Up: Preview Framing

Post-deployment inspection found an integration blocker not covered by the first
backend conversion checks: the root application's CSP used `frame-src 'none'`,
and the viewer inherited an application `X-Frame-Options: DENY` response. Valid
documents and healthy conversion services alone did not establish browser display.

The follow-up permits only same-origin child previews and makes an embedding
exception only for the exact self-hosted PDF.js viewer HTML. The application itself
remains non-embeddable, other application responses retain their frame protection,
and the viewer receives a local-only connection policy. No external document
viewer or new third-party access was introduced.

926 backend tests and all 17 frontend suites passed. New tests cover both framing
headers and packaged runtime bundles. Public post-deployment checks confirmed
the effective headers without a conflicting viewer denial, valid viewer asset
hashes/MIME types, authorization boundaries and available PDF/DOCX/DOC/TXT route
outputs. Deployment is `clean-20261109t072310z`; the unchanged converter retains
its previously verified image and real conversion rehearsal. Data, other services
and AI usage were preserved. Reload an already-open application page to receive
the new policy. Fresh visual canvas verification remains outstanding.

## Document Preview Design

- PDF: original pages, including scans, through self-hosted Mozilla PDF.js 6.5.438.
- DOC/DOCX: private LibreOffice conversion to PDF, without modifying the source.
- TXT: original bytes decoded as UTF-8/BOM Unicode or common Windows text encoding,
  rather than limiting the document view to the cached 80,000-character excerpt.
- PDF.js provides page, zoom, search, selection and password-prompt controls. Its
  document scripting, annotation editing, preference overrides and AI/alt-text
  model downloads are disabled before initialization. Assets load only on demand.
- The document endpoint authorizes the upload ID on every request, including
  conversion-cache hits. Responses are private/no-store and MIME-restricted.
- Source size is capped at 16 MiB and generated PDF output at 32 MiB. Word conversion
  has one application slot, a 30-second worker deadline and a bounded five-minute,
  64 MiB application-memory cache. No CV goes to an external viewing service.

See `deploy/vps/preview/README.md` and the vendored PDF.js provenance/license notes.
